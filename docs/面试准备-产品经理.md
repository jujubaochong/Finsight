## 一、自我介绍

> 原则：自我介绍 = 我是谁 + 我做过什么有代表性的事 + 为什么适合这个岗位。**别背简历流水账，要有一个"钩子"让面试官想追问**——这个钩子就是 FinSight。

### 1.1 30 秒电梯版（面试开场默认用）

> 面试官好，我是 ___，背景是 ___（专业/上一段经历）。我对 AI + 金融方向的产品特别感兴趣，最近独立做了一个叫 FinSight 的 AI 投研助手——用户输入一个股票代码，30 秒就能拿到一份 AI 生成的结构化分析报告。这个项目我从市场洞察、竞品分析、写 PRD 一直到全栈实现上线全程一个人完成。我比较擅长的是"把模糊的用户痛点拆成能落地的产品方案"，也因为自己写代码，对技术可行性和成本有判断。希望能应聘贵司的产品经理岗位。

### 1.2 1–2 分钟标准版（结构：背景 → 代表作 → 能力关键词 → 动机）

> 面试官好，我是 ___。先说背景：___（一句话教育/工作经历）。
>
> 我想重点讲一个能代表我产品能力的项目——FinSight，一个面向个人投资者的 AI 投研助手。它的起点是一个我自己也踩过的痛点：想研究一只股票，得在同花顺、东方财富、雪球、巨潮之间来回切，花了 15 分钟还是看不懂这家公司到底怎么样。我观察了几位身边有同样困扰的用户后确认这是个普遍问题，于是把产品定位成"输入代码 → 输出一份帮你划好重点的分析报告"。
>
> 这个项目里我做了几件事：用竞品分析找到了市场空白——所有工具都在"给你看数据"，没人"帮你理解数据"；用 MoSCoW 和一份"不做清单"把范围压到单人能交付的 MVP；设计了 AI 的分层能力和防幻觉、合规策略；还定义了北极星指标和转化漏斗。最后我用 FastAPI + React 把它全栈实现并上线了，过程中还自己解决了几个线上级的稳定性问题。
>
> 我觉得我比较适合产品岗的点是：**既能下沉到用户场景做减法，又因为懂技术能让 PRD 真正落地**。这也是我想做 PM 的原因——我享受"定义对的问题，再把它交付出来"的完整过程。

### 1.3 把项目自然带进自我介绍的"钩子句"

挑一句最容易引发追问的话收尾，主动把节奏引到你最熟的项目上：

- "其中我最有感触的是用竞品分析找到差异化定位的过程，待会儿可以展开聊。"
- "这个项目让我第一次完整体验了'砍需求比加需求更难'，如果感兴趣我可以讲讲我的取舍。"

## 二、项目介绍（分层版本）

> 面试官问"介绍一下你的项目"时，**先给一句话，再问对方想听哪个角度**（产品决策 / 用户 / 技术 / 数据），别一上来讲 5 分钟。下面按时长准备 3 个版本 + 1 张数据卡。

### 2.1 一句话版
> FinSight 是一个 AI 投研助手——个人投资者输入 A 股代码，30 秒就能拿到一份 AI 生成的结构化个股分析报告，替代在 3–4 个 App 之间来回查找的碎片化体验。

### 2.2 30 秒版（背景 + 方案 + 我的角色）
> 个人投资者研究一只股票时，数据散落在同花顺、东财、雪球、巨潮，而且都是"陈列数据"不"解读数据"。FinSight 把这条链路收成一个动作：输入代码，输出一份包含"一句话结论 + 3 个亮点 + 3 个风险 + 关键指标解读"的报告，还能生成深度研报、监控自选股异动。我是这个项目的产品负责人兼全栈开发，独立完成了从 0 到 1。

### 2.3 2 分钟版（推荐主用，结构：问题 → 洞察 → 方案 → 取舍 → 结果）

> **问题**：我发现个人投资者研究股票时工具链是断裂的——行情在同花顺、财务在东财、讨论在雪球、公告在巨潮，没有一个地方能"一站式看完"，而且这些工具都在给你看数据，不帮你理解数据。普通人花 15 分钟还是不知道这家公司好不好，最后干脆放弃研究。
>
> **洞察**：我体验了 4 款主流竞品后发现，市场是哑铃形的——一端是面向散户的轻量 AI 问答（够不着深度），一端是 Wind 这种机构终端（一年几万块、还难用）。中间有一群"想深入研究但够不着机构工具"的用户没被服务好。这就是 FinSight 的卡位。
>
> **方案**：核心差异是从"问答式数据查询"升级成"结构化报告生成"——输入代码就输出研报，而不是输入问题输出答案。具体功能有智能搜索、10 秒 AI 快速分析、财务可视化、异步深度研报、自选股异动监控，最近还加了一个"决策对照台"——把 AI 的风险收益预估和用户自己的预期做对照。
>
> **取舍**：我刻意砍掉了交易、买卖建议、实时行情/K线、社区。前两个是合规红线和打不过的入口，后两个是没有差异化、且社区冷启动必死。砍掉它们才让 MVP 单人可交付。
>
> **结果**：我独立用 FastAPI + React 把它实现并上线内测。我设计了北极星指标（周活跃搜索用户）和验证假设的方法，目前在用真实用户验证"AI 报告比碎片化问答更有价值"这个核心假设。

## 三、项目细节追问（含参考答案）

> 这是面试的重头戏——面试官会顺着你的介绍往下挖。下面按主题分组，每题给"答题要点 + 参考话术"。**练的时候出声说，控制在 1 分钟内**。

### A. 动机与定位

**Q1：你为什么做这个项目？**
- 要点：真实痛点（自己/身边人）+ 你判断它普遍 + 你对方向的兴趣。
- 话术：起点是我自己研究股票时的挫败感——工具多但串不起来。我又观察了几个有同样困扰的朋友，确认不是个例。加上我对 AI 落地到垂直场景很感兴趣，就决定拿它练一个完整的 0→1。

**Q2：为什么是"报告生成"而不是做一个更好的问答机器人？**
- 要点：问答是"被动应答"，用户得知道问什么；报告是"主动给框架"，正好补"缺乏分析框架"这个痛点。
- 话术：我的目标用户恰恰是"不知道该问什么"的人。问答要求用户已经有分析框架，而他们没有。报告生成等于"有人替你读过、划好重点了"，这才是他们要的。

### B. 用户与需求

**Q3：你的目标用户到底是谁？怎么确定的？**
- 要点：不是"所有散户"，是"有研究意愿但被工具门槛劝退"的人；用画像 + 反向定义"非目标用户"。
- 话术：主攻画像是"张弛"——31 岁、有一定认知但不会拆财报。我同时明确了非目标用户：短线打板、纯买基金、跟单族都不是。把谁排除掉，比说服务谁更重要。

**Q4：你怎么验证这是个真需求，而不是你自己的伪需求？**
- 要点：给出可证伪的假设 + 验证方式 + 目标阈值（体现科学性）。
- 话术：我把它拆成 3 个假设：需求假设（有人愿意研究基本面）、价值假设（AI 报告够好到值得读完）、留存假设（用完会回来）。比如价值假设的验证是：找 10 个用户盲测 AI 报告 vs 同花顺问财，目标 >70% 选 AI 报告。需求假设是发 Demo 链接看一周搜索量。

**Q5：用户为什么会用你而不是免费的同花顺问财？**
- 要点：差异在"深度 + 报告结构 + 主动发现风险"，是认知/体验差不是功能堆叠。
- 话术：问财给你播报数据，我给你一份带结论和风险清单的报告，还会主动指出"这家商誉占净资产比例偏高"这类用户自己想不到去看的点。

### C. 竞品与差异化

**Q6：这个赛道这么卷，凭什么是你？/ 如果同花顺明天上线一样的功能怎么办？**
- 要点：承认技术不是壁垒，壁垒在"产品认知 + 聚焦"，再给护城河。
- 话术：我不认为技术是壁垒——大厂随时能抄。我的判断是：大厂的问答功能服务的是"全体散户"，做不深也不敢做太垂直；而我聚焦"想深研的人"，可以在分析框架和报告质量上做到极致。真正的护城河是产品认知差、加上后续的用户数据飞轮。短期我靠"专注 + 体验差"活下来。

**Q7：你做了哪些竞品分析？怎么做的？**
- 要点：方法（实际深度使用，不是看介绍）+ 结论（能力矩阵 + 空白地带）。
- 话术：我把同花顺问财、东财妙想、雪球 AI、Wind 各用了半小时以上，模拟真实研究场景，输出了一张能力矩阵。结论是它们都缺"报告生成"和"主动风险发现"两个维度，市场呈哑铃形、中间是空白。

### D. 优先级与取舍

**Q8：功能这么多，你怎么排优先级？**
- 要点：MoSCoW + 判断标准（是否服务核心假设/核心用户）。
- 话术：我用 MoSCoW 分四档，判断标准是"是否直接验证核心假设、是否服务主攻用户张弛"。比如"AI 快速分析"是 Must（它直接验证价值假设），"行业对标"放到 V1（锦上添花），"多市场"放到 V2。

**Q9：你砍掉的功能里，哪个最纠结？为什么还是砍了？**
- 要点：挑"行业对标"或"实时行情"，讲清取舍逻辑（资源有限 + 不服务核心假设）。
- 话术：最纠结的是行业对标——它确实能提升分析深度。但 MVP 阶段我要先验证"AI 报告本身有没有价值"这个更前置的假设，对标属于"报告已经有人看了之后再增强"的事，所以放到 V1。砍需求最难的是克制，而不是判断。

**Q10：如果只能保留一个功能，你留哪个？**
- 话术：AI 快速分析。因为它是整个产品价值假设的最小验证单元——如果用户连这 10 秒的报告都觉得没用，后面的深度研报、监控都没意义。

### E. AI 与技术

**Q11：AI 会乱编数据（幻觉）怎么办？金融场景这很致命。**
- 要点：3 层防线，体现你对 AI 产品风险的认知。
- 话术：我设计了三层防线：① 所有数字只允许从源数据引用、不让模型自己算；② 每个数据点标注来源、可追溯；③ 把"数据事实"和"AI 推断"在 UI 上显式分开，让用户知道哪些是客观、哪些是观点。另外正式上线会标注"仅供参考、非投资建议"。

**Q12：为什么用 90% DeepSeek + 10% Claude？为什么链式调用？**
- 要点：成本/质量权衡 + 工程可控性。
- 话术：DeepSeek 便宜（约 $0.27/1M tokens），覆盖大部分常规分析；少量需要复杂推理的环节用 Claude 保质量。链式调用而不是一把梭，是因为单步 Token 可控、单步失败可重试、还能在中间插入审核——对金融内容更稳。

**Q13：作为 PM 你为什么要自己写代码？这不是浪费时间吗？**
- 要点：把"懂技术"转化为产品价值，而不是炫技。
- 话术：对个人项目它是必要的，但更重要的是它让我对技术可行性和成本有判断——我写 PRD 时能预判哪些功能是"一句话需求、一周工作量"，不会画饼。它也让我和研发沟通时有共同语言。

**Q14：项目里遇到的最大技术挑战？（这题也能当行为题）**
- 故事 1（启动假死）：后端启动时好时坏，我通过对比日志和数据库状态，定位到启动时同步执行行业基准计算、会对每只股票逐一发起网络请求，数据量一大就退化成数千次同步调用。我把它改成只读 + 后台执行，启动从数分钟降到秒级。
- 故事 2（数据抓不到）：东方财富对 Python 请求做了 TLS 指纹拦截，资金流数据一直拉不到。我先强制 IPv4 直连，再用 curl 子进程做兜底绕过指纹检测，才把数据稳定拿到。
- 收尾：这两件事让我体会到"产品的体验承诺，最后要靠工程细节兜底"。

### F. 指标与商业化

**Q15：你怎么衡量这个产品成功？北极星指标是什么？**
- 要点：北极星 = 周活跃搜索用户数，并解释为什么不选"报告生成数"。
- 话术：北极星是周活跃搜索用户数（WAU）。因为"搜索"是用户获得首次价值的入口，同时反映拉新和留存。我没选"报告生成数"是因为它容易被运营手段刷高，但不代表真实价值。

**Q16：上线后某个指标（比如次日留存）下降了，你怎么排查？**
- 用框架答（见第四部分 4.4），并落到项目：先分维度（新/老用户、渠道、机型），再看漏斗哪一环掉的，再提假设、做验证。

**Q17：这个产品怎么赚钱？商业模式想过吗？**
- 要点：诚实分阶段——先验证价值再谈变现；给出方向。
- 话术：MVP 阶段不考虑变现，先验证价值和留存。方向上我倾向 freemium：免费用户有次数限制的快速分析，付费解锁深度研报、批量赛道扫描、自选监控这些"专业用户"高频功能——也就是先服务张弛拉量，再向赵明远这类有付费意愿的半专业用户变现。

### G. 反思

**Q18：如果重做，你会改什么？**
- 话术：我会更早做用户验证。前期我花了不少时间打磨文档和功能，其实应该先用一个最粗糙的 Demo 去测"价值假设"，再决定投入多少。我把"想清楚"和"验证清楚"搞混了。

**Q19：这个项目最大的不足/风险是什么？**
- 话术：最大风险是 AI 分析质量的天花板——如果它只比问财好一点点，不足以让用户切换。我的应对是规则引擎保底 + Prompt 持续迭代，并把它作为最该被验证的假设。

## 四、PM 通用面试题（题型 + 框架 + 示范）

> 这一部分练"题型反应"。每种题型记住一个框架，临场套；能关联到 FinSight 的就关联，体现"知行合一"。

### 4.1 产品设计题 —— "设计一个 X" / "为 Y 用户设计一个 Z"
**框架：CIRCLES（精简记 5 步）**
1. **澄清**：用户是谁？什么场景？要解决什么？平台/约束？（先问，别急着答）
2. **用户与痛点**：列 2–3 类用户，挑一类最痛的聚焦。
3. **需求/方案**：头脑风暴方案，按价值×成本排优先级。
4. **取舍**：明确做什么、不做什么，说理由。
5. **指标**：怎么衡量成功（北极星 + 一两个辅助指标）。

**示范开场**："在我开始之前，我想先确认几个问题——这个产品的目标用户主要是谁？我们更看重拉新还是留存？有没有平台限制？" ← 主动澄清是这类题的最高分动作。

### 4.2 产品分析/吐槽题 —— "你最近用的某产品，怎么改进？"
**框架**：产品目标 → 目标用户 → 当前体验亮点 → 1 个核心问题（聚焦，别罗列）→ 改进方案 → 如何验证（指标/AB）。
**提示**：选你真懂的产品，深挖一个点，比泛泛吐槽五个点强得多。

### 4.3 估算题（Fermi）—— "估算 X 的市场规模/日活/数量"
**框架**：自上而下或自下而上，**讲清假设比算对数字重要**。
- 步骤：定义范围 → 找一个锚点（人口/用户基数）→ 逐层乘以转化率/比例 → 给区间 → 做合理性检验。
- 示范思路（A 股投研产品潜在用户）：中国股民约 2 亿 → 个人投资者占大头 → 其中"有基本面研究意愿"的比例假设 10–15% → 再乘以智能手机/愿意尝试新工具比例……每一步都说出假设来源。

### 4.4 指标/数据题 —— "某指标下降了，怎么排查？"
**框架：先定义 → 拆维度 → 看漏斗 → 提假设 → 验证**
1. **确认**：是真下降还是统计口径/埋点问题？下降幅度、时间点？
2. **拆维度**：新 vs 老用户、渠道、地区、机型、版本——定位是整体还是局部。
3. **看漏斗**：是哪一环掉的（曝光→点击→激活→留存）。
4. **内外因**：内部（发版、改版、bug、活动结束）vs 外部（竞品、季节、舆情）。
5. **提假设 + 验证**：形成最可能的假设，用数据或小实验验证，再给方案。
**口诀**：先确认真假，再拆维度定位，最后才谈解决。

### 4.5 优先级题 —— "这几个需求你先做哪个？"
**框架：RICE**（Reach 覆盖 × Impact 影响 × Confidence 信心 ÷ Effort 成本），或 **Kano**（基本型/期望型/兴奋型）。
**关键**：说出你的判断标准（是否服务核心假设/核心用户/北极星），而不是凭感觉。

### 4.6 行为题（STAR）—— 冲突 / 失败 / 推动 / 抗压 / 领导力
**框架：STAR**（情境 Situation → 任务 Task → 行动 Action → 结果 Result，重点在 A）。
可复用的 FinSight 素材：
- **"克服困难/抗压"**：东财 TLS 指纹拦截导致数据抓不到 → 强制 IPv4 + curl 子进程兜底解决。
- **"做艰难取舍"**：砍掉行业对标/社区，聚焦核心假设。
- **"从失败中学习"**：前期过度打磨文档、太晚做用户验证。
- **"系统化解决问题"**：启动假死的根因定位与修复。
> 没有团队冲突类素材？可以用"与'过去的自己'的冲突"——即想加功能的冲动 vs 必须聚焦的克制，照样能讲出取舍。

### 4.7 动机题 —— "为什么做 PM？为什么我们公司/这个岗位？"
- **为什么做 PM**：我享受完整的"定义对的问题 → 推动它被交付"的过程；FinSight 让我验证了自己既能做减法、又能落地。
- **为什么这家公司**（需按 JD 定制）：提前研究公司产品，说出 1 个你真实欣赏的点 + 1 个你能贡献的点。**别说"平台大、能学习"这种空话**。

### 4.8 "你最喜欢的产品是什么？"
**框架**：是什么 → 解决了什么问题 → 你欣赏的 1 个产品决策（要具体到细节）→ 如果是你会怎么再改进。体现你"带着产品视角用产品"。

## 五、反问环节（问面试官）

> 反问 = 加分项，体现你想清楚了。准备 4–5 个，按对象选 2–3 个问。

**问业务/产品**
- 这个岗位负责的产品当前最大的挑战是什么？
- 团队怎么定义这个产品的成功？看哪个核心指标？

**问团队/协作**
- PM 在这里和研发、设计、运营是怎么分工协作的？
- 一个需求从想法到上线的典型流程是怎样的？

**问成长/期望**
- 这个岗位入职后 3–6 个月，您期望我做出什么成果？
- 团队里做得好的 PM 通常具备什么特质？

> ❌ 别问：能查到的（公司规模）、薪资福利（留到 offer 环节）、"你们加班多吗"这类负面开场。
